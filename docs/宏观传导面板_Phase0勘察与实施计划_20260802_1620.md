## 二、⭐ 接口验证结果（全部实际调用）

### 2.1 北向资金 —— 比你描述的情况**更危险**

你的判断方向正确，但实际情况不是"字段变空"，而是 **字段还在、有值、含义变了**：

```
2026-08-16  north_money =  -6774.99   ← 净买入（可为负）
2026-08-19  north_money = +88110.55   ← ⭐口径变更当日，跳 13 倍
2026-08-20  north_money = +89201.95
...
2026-07-31  north_money = +354101.65
```

> **勘误（第二轮修正）**：初版我把「`north_money` 精确等于 `hgt+sgt`」当成证据，**这是错的**——
> 那是恒等式（北向=沪股通+深股通），口径变更前后都成立，不构成任何证据。已删除。
> 同时初版单位写成"万元"也是错的，**正确单位是百万元**。下面是重做的、可自证的证据。

**字段单位**：百万元。故 `-6774.99` = **净卖出 67.75 亿元**，`88110.55` = **881.11 亿元**。

**证据一 · 量级自证（不依赖任何外部报道，可用本项目数据复算）**
把变更后的 `north_money` 与**同日全A成交额**（本项目 `get_daily` 的 `amount` 汇总）相比：

| 交易日 | 北向值(亿元) | 全A成交额(亿元) | 占比 |
|---|---|---|---|
| 20260724 | 2838 | 19445 | 14.6% |
| 20260727 | 2769 | 20887 | 13.3% |
| 20260729 | 3414 | 23117 | 14.8% |
| 20260730 | 3635 | 23584 | 15.4% |
| 20260731 | 3541 | 25599 | 13.8% |

**每天稳定占全市场成交额 14%±1%**。净买入是买卖轧差后的净额，**必然远小于成交额**，
一个渠道的净流入不可能天天等于全市场成交额的七分之一 → **只能是成交额口径**。

**证据二 · 分布形态突变**

| | 均值 | 区间 | 有无负值 |
|---|---|---|---|
| 变更前一周（8/12–8/16） | **-10.1 亿** | [-71.7, +122.1] | **有** |
| 变更后一周（8/19–8/23） | **+863.2 亿** | [826.0, 892.0] | **无** |

变更前：有正有负、围绕 0 波动 → 净额形态。
变更后 300 个交易日 **为负占比 0.0%**，且区间极窄（826~892 亿）→ 成交额形态。

**结论**：`moneyflow_hsgt.north_money` 自 2024-08-19 起 **已从「净买入」变成「成交额」**。
若照搬做"北向净流入"卡片，会**每天显示巨额净流入**——这是个会持续误导的错误，比空值危险得多。

**处置**：
- 只做 `northbound_turnover`（成交额=活跃度代理），`direction=0`（中性），
  `note` 明确写"2024-08-19 口径变更：此前为净买入，此后为成交额，两段**不可拼接比较**"
- 分位/zscore 的历史窗口**必须从 2024-08-19 起算**，绝不能跨越断点
- `south_money` 同样全正且区间异常窄（42919~54910），Phase 1 **暂不采用**，待单独核实

### 3.3 建表 DDL（按项目 SQLite 约定改写）

存放位置建议：**独立文件 `data_cache/macro.db`**（不塞进 `strategy.db`）。
理由：宏观数据可独立重建/回补/清空，不牵连策略库；且完全不需要动 `app/strategy/db.py` 一行。

```sql
-- 指标元数据（配置驱动的唯一真源；前端与计算层都不得硬编码指标列表）
CREATE TABLE IF NOT EXISTS metric_meta (
    code        TEXT PRIMARY KEY,          -- 'fdr007' / 'cn_10y' / 'limit_up_cnt'
    name_cn     TEXT NOT NULL,
    layer       TEXT NOT NULL,             -- L0_liquidity|L1_flow|L2_sentiment|L3_external
    freq        TEXT NOT NULL,             -- daily|weekly|monthly
    unit        TEXT,                      -- bp|亿元|%|家|点
    direction   INTEGER NOT NULL DEFAULT 0,-- 1=高对A股偏多 -1=偏空 0=中性
    weight      REAL    NOT NULL DEFAULT 1.0,
    source      TEXT,                      -- tushare|akshare|internal
    api         TEXT,                      -- 具体接口名，排查用
    lag_days    INTEGER NOT NULL DEFAULT 0,
    enabled     INTEGER NOT NULL DEFAULT 1,
    hist_break  TEXT,                      -- 历史断点日 YYYYMMDD（如北向 20240819），分位窗口不得跨越
    note        TEXT,
    sort_order  INTEGER NOT NULL DEFAULT 100,
    updated_at  TEXT DEFAULT (datetime('now','localtime'))
);

-- 指标日频长表
CREATE TABLE IF NOT EXISTS macro_daily (
    trade_date    TEXT NOT NULL,           -- YYYYMMDD（交易日）
    code          TEXT NOT NULL,
    value         REAL,                    -- NULL = 未更新（禁止用 0 或昨值填充）
    chg_1d        REAL,
    chg_5d        REAL,
    zscore_250    REAL,
    pctile_750    REAL,                    -- 0-100，point-in-time
    as_of         TEXT,                    -- 该数值对应的真实数据时点 YYYYMMDD
    is_stale      INTEGER NOT NULL DEFAULT 0,  -- 1 = forward fill 而来（月频/未更新）
    ingested_at   TEXT DEFAULT (datetime('now','localtime')),
    source_run_id TEXT,
    PRIMARY KEY (trade_date, code)
);
CREATE INDEX IF NOT EXISTS idx_macro_code_date ON macro_daily(code, trade_date);

-- 取数运行日志（§8 验收：看到每个指标的成功/失败/耗时）
CREATE TABLE IF NOT EXISTS macro_run_log (
    run_id      TEXT NOT NULL,
    trade_date  TEXT NOT NULL,
    code        TEXT NOT NULL,
    status      TEXT NOT NULL,             -- ok|empty|error
    elapsed_ms  INTEGER,
    err_msg     TEXT,
    created_at  TEXT DEFAULT (datetime('now','localtime')),
    PRIMARY KEY (run_id, code)
);

-- 事件日历（支持手工录入）
CREATE TABLE IF NOT EXISTS macro_calendar (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    event_date  TEXT NOT NULL,             -- YYYYMMDD
    event_type  TEXT NOT NULL,             -- fomc|us_cpi|us_nfp|cn_data|lpr|meeting|earnings|float_release
    title       TEXT NOT NULL,
    importance  INTEGER NOT NULL DEFAULT 2,-- 1低 2中 3高
    region      TEXT,                      -- CN|US|HK|GLOBAL
    expected    TEXT,                      -- 市场预期（可空）
    actual      TEXT,                      -- 实际值（发布后回填）
    note        TEXT,
    is_manual   INTEGER NOT NULL DEFAULT 0,
    UNIQUE(event_date, event_type, title)
);
CREATE INDEX IF NOT EXISTS idx_cal_date ON macro_calendar(event_date);

-- 每日 LLM 摘要存档
CREATE TABLE IF NOT EXISTS macro_summary (
    trade_date  TEXT PRIMARY KEY,
    liquidity   TEXT,
    flow        TEXT,
    external    TEXT,
    model       TEXT,
    created_at  TEXT DEFAULT (datetime('now','localtime'))
);
```

**相对你原 DDL 的改动**（都请你过目）：
1. 类型改 SQLite 约定；日期改 `TEXT YYYYMMDD`；`BOOLEAN`→`INTEGER 0/1`

## C. Point-in-time 分位窗口策略（按你要求：不足就留空，不短窗凑数）

**三条硬规则**：
1. **不足 250 个有效样本 → 分位/zscore 一律写 NULL**，前端显示「分位样本不足 (N/250)」，

## G. 跨库 ATTACH 用法（写进口径文档，此处先给出）

```sql
-- 只读跨库：宏观状态 × 策略记录（回答"什么宏观环境下我的选股有效"）
ATTACH DATABASE '/home/ubuntu/astock-agent/data_cache/strategy.db' AS s;

SELECT m.trade_date, m.pctile_750 AS 流动性分位, AVG(p.pct_return) AS 平均收益
FROM macro_daily m
JOIN s.selection_records r ON r.run_date = m.trade_date
JOIN s.performance_records p ON p.selection_id = r.id AND p.horizon = 5
WHERE m.code = 'fdr007' AND m.pctile_750 IS NOT NULL
GROUP BY CAST(m.pctile_750 / 20 AS INT);
```
**注意**：两库均为 WAL 模式，跨库**只读 join 安全**；
